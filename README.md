# HORTOS Constitution

> The operating system for landscape stewardship.

HORTOS is a property-first, field-first operating system for professional horticulture and landscape service companies. This repository is the canonical source of truth for HORTOS product, design, engineering, data, AI, and operating decisions.

It is built to support a multidisciplinary team of 20+ contributors while preserving founder intent and architectural coherence.

## Start here

1. Read [`START-HERE.md`](START-HERE.md).
2. Check [`STATUS.md`](STATUS.md) for the current state.
3. Review [`ROADMAP.md`](ROADMAP.md) for what comes next.
4. Use [`OPEN-DECISIONS.md`](OPEN-DECISIONS.md) for unresolved founder or architecture decisions.
5. Read [`GOVERNANCE.md`](GOVERNANCE.md) and [`CONTRIBUTING.md`](CONTRIBUTING.md) before proposing changes.

## Core operating belief

The repository should always answer:

1. What is HORTOS?
2. What has already been decided?
3. What is being worked on now?
4. What should happen next?

The founder should not have to remember project state. The repository must remember it.

## Authority order

When documents conflict, use this order:

1. Accepted decision records
2. Approved constitutional documents
3. Approved specifications
4. Current roadmap and status
5. Drafts and research

A conflict should be resolved in the repository, not informally in chat.
