# HORTOS Constitution — Project Status

## Current phase

**Phase 0: Repository Governance v1**

Objective: create a durable operating system for a 20+ person product and engineering organization before expanding the product constitution.

## Overall state

| Area | State | Notes |
|---|---|---|
| Repository access | Complete | GitHub write access verified |
| Governance spine | In progress | Core navigation and management files being established |
| Constitutional foundation | Not started | Begins after governance acceptance |
| Core domain model | Not started | Property, client, visit, agreement, plant, route |

| Engineering architecture | Not started | Platform, data, offline sync, permissions, APIs |
| AI architecture | Not started | Field intelligence and agent behavior |
| Delivery specifications | Not started | Screen, workflow, acceptance, and integration specifications |

## Completed

- Repository created and connected.
- Canonical repository purpose defined.
- Authority hierarchy established.
- Contributor onboarding entry point created.
- Founder-memory requirement adopted: the repository must track what is done and what comes next.

## Active work

- Founder dashboard and phased roadmap.
- Governance and contribution standards.
- Decision-record system.
- Documentation templates and metadata standards.
- Initial constitutional decisions.

## Next recommended actions

1. Complete Repository Governance v1.
2. Establish HORTOS North Star and product principles.
3. Define the shared vocabulary and core domain map.
4. Approve the first product and architecture decisions.
5. Begin the Property domain specification.

## Founder attention required

None currently. The governance foundation can proceed under the established direction.

## Risks being controlled

- Documentation sprawl without authority.
- Duplicate concepts and inconsistent naming.
- Decisions remaining trapped in chat or memory.
- AI agents treating drafts as approved specifications.
- Roadmap drift and unclear ownership.
- New contributors being unable to orient quickly.

## Definition of Phase 0 complete

Phase 0 is complete when:

- all repository management files exist;
- document and decision templates are usable;
- contribution and review rules are explicit;
- the roadmap identifies all major constitution workstreams;
- first constitutional decision records are accepted;
- a new contributor can identify current state and next work within 15 minutes.
